## What I got wrong, specifically

1. **I treated non-persistence as a safeguard** (XR-01). Not storing a number does not make inferring it approved. The gate is the right mechanism and I should have reached for it when I built the payment gate.
2. **I let a description stand in for a constraint** three times — `rationale` "positive framing", `preferences` "never accepted here", and `budgetCents` trust (XR-02, XR-13, XR-12). A promise a test cannot check is not a safeguard.
3. **I summed the ledger without regard to provenance** (XR-03, XR-04), so fixture money and unverified rows could have gated a real payment. That is the most serious of the defects.
4. **I declared a non-negative type for a signed sum** (XR-05) — an internal contradiction in a single schema.
5. **I never worked out what pause means** (XR-07). It silently broke the seat cap and the agreement rules in three different ways.
6. **I built a dependency deadlock** (XR-29) and the repository test could not catch it, because open questions are not task rows.
7. **I overstated verification** (XR-27): the operation count was wrong and ADR 0004 claimed metaschema validation that never ran.

## What this response does not do

No policy was decided, no gate was opened, and no Lane A file was edited. Q-001 is answered by ADR 0005; **Q-002, Q-005 and Q-006 remain open**. The freeze (YT-014) still cannot proceed until YT-024 and YT-025 report. The reverse half of touchpoint T4 — my review of the Lane A drafts — is still owed.
